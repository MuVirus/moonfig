# decisions 指南

决策记录讲「当时为什么这么定」。记录已经踩过并定了结论的事；长期有效的设计叙述放
`design/`。

## 文件

- [`decisions.zh.md`](decisions.zh.md) —— 编号决策记录、顶部状态索引、每条决策的状态行。

编号、状态和影响文档以 [`decisions.zh.md`](decisions.zh.md) 顶部的索引为准；本文件不重复维护一份。

## 规则

- 每个编号标题下写一行 `状态：<状态>｜影响：<路径>`；顶部索引同一行必须一致。
- 状态只用 `生效` / `部分被取代` / `已取代` / `作废`；取代关系写在括号里，例如 `生效（取代 #11）`。
- 被取代时两边都写 `#N`：旧条目写 `部分被取代（#N ...）`，新条目写 `生效（取代 #N ...）`。
- `影响` 写相对 `docs/` 的路径，多个用 `、` 分隔；纯实现约定写 `无（仅实现）`。
- 写清日期、实测或证据、结论的代价；没有证据的偏好不写进来。
- 一次决定一条；新增条目后更新顶部索引。
