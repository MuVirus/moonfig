# 任务指南

`docs/guides/` 面向「我要做成 X」。设计取舍放 `design/`，可运行证明放 `examples/`。

- 一篇一个任务，文件名写清做什么：`layer-sources.md`、`choose-extraction.md`。
- 固定五段，顺序不变：
  1. **适用场景**：什么情况下用，什么情况下不用。
  2. **前置条件**：依赖、环境、需要先读的文档。
  3. **完成标准**：做完后能观察到什么；写不出来就不是任务。
  4. **步骤**：编号步骤；代码只做示意，完整代码链到 `examples/`。
  5. **常见坑与下一步**：会踩的坑，以及接下来该读哪篇。
- 控制在约 80 行；超过就拆成两篇，或把细节移进 `design/`。
- 影响照着做的术语（如 `Getter`、`Int64Text`）在第一次出现处用一句话解释；背景术语
  链到 `design/`，不搬整张术语表。
- 不复制 API 表、错误表、设计取舍；链接到 `design/` 或 `reference/`。
- 与 `design/` 冲突时以 `design/` 为准，并修正 guide。
- 每篇至少链一个可运行 example。

审查时问：读者能照着做到「完成标准」吗？每段都有内容吗？有没有能改成链接的重复事实？
