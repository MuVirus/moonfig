# 文档写作

文档是「原则指引」与「名词解释」，不是代码的镜像。读者看文档，是为了比翻代码更快、更准地理解意图。

落笔前问一句：**读者直接看代码是不是更快？** 如果是，就给链接，不要复制。

## 该写什么

- 为什么这样定：设计背后的取舍、文件分类的原则。
- 不明显的坑：平台怪癖、隐蔽的约束，比如「删掉 X 会让 Y 崩」。
- 指路：东西放在哪、放什么类型的内容、按什么规则归类。
- 结论先行：先给规则，再给理由；实测数据写明来源。

## 该删什么

- 代码的复读机：类名、文件清单、枚举值、命令矩阵。
- 流水账：改了什么、删了什么、试过哪些废案。
- 数得出来的统计：数量、行号等读代码就知道的信息。
- 一段散文能用一个链接替代的废话。

## 链接与单一事实来源

- 每个事实只有一个权威位置，其他文档用 Markdown 链接指过去，禁止复制。
- 英文是权威版本；中文副本用 `.zh.md`，只做翻译，不新增事实。两者不一致时以英文为准。
- 向下导航：根节点链到子文档，子文档链到具体模块。
- 不用方位词。不写「下面」「如上所述」「见第 3 节」，直接给链接。

## 审查一轮

看到这三种情况，直接删：枚举代码已有信息、叙事废话、抄了别处已有的事实。一句话能靠链接解决的，就换成链接。
